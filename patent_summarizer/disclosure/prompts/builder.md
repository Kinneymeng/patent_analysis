# 发明研发技术交底书 Builder

依据已经确认的完整技术方案撰写交底书。不得在成文阶段改变确认的核心机制。正文必须包含六章，并保持以下标题和顺序：

一、技术背景与现有方案
二、需要解决的技术问题
三、技术方案详细说明
四、技术效果与适用边界
五、技术关键点
六、实施例与验证方法

第三章应按实际需要设置小节，至少说明应用场景与术语、系统架构、模块职责及输入输出、流程、数据流和控制流、异常及边界处理。只有方案确实需要时才写公式和参数。

用户确认方案中的具体模块名、每项输入输出、技术关键点、流程步骤编号和示例参数必须逐项保留。可以补充解释，不得改名、遗漏或把示例参数写成已经定型的实测参数。

查新状态为成功或部分完成时，第一章保留检索时间，并逐条保留已选记录的真实公开号、标题、IPC 分类号、国知局来源链接和实际读取内容，再说明与本方案的具体异同。状态为无相关结果时，只能说明本次检索的时间、检索词和“在该检索范围内未筛选出可核验记录”，不得扩大为“没有相似专利”。查新未启用或失败后跳过时，不得写“经查新”“已经查新”“未发现相似专利”等结论。

图示必须包含一张系统架构图和一张流程图，使用受限 Mermaid `flowchart TD` 语法。使用普通节点、判断节点和 `-->` 连线，不使用脚本、链接、自定义样式或复杂子图。每个节点标签使用具体对象或动作，流程节点可见标签包含 S1、S2 等步骤号。图中的节点和正文模块、步骤必须一一对应。

实施例覆盖正常主路径和至少一条已经在第三章描述的异常或边界路径，明确输入、处理过程、预期输出和验证方法。技术效果说明技术手段与效果之间的因果关系，区分预期效果与有材料支持的已验证结果。

只输出 JSON：

  "摘要": "单一自然段",
  "章节": [

      "标题": "技术背景与现有方案",
      "段落": ["……"],
      "小节": [{"编号": "1.1", "标题": "……", "段落": ["……"]}]
    }
  ],
  "图示": [
    {"章节": "三", "类型": "系统架构图", "标题": "图1 ……", "mermaid": "flowchart TD\nA[具体输入] --> B[具体模块]"},
    {"章节": "三", "类型": "流程图", "标题": "图2 ……", "mermaid": "flowchart TD\nS1[S1 采集数据] --> S2[S2 处理数据]"}
  ],
  "参数表": [
    {"章节": "三", "标题": "关键技术参数", "表头": ["参数", "符号", "含义", "值或范围", "确定依据"], "行": [["……"]]}
  ],
  "公式": [
    {"章节": "三", "编号": "式（1）", "LaTeX": "……", "说明": "……", "来源": "source或agent", "材料依据": "……"}

}

没有必要公式时“公式”必须为空数组；没有必要参数表时“参数表”可以为空数组。不得为显得复杂而编造公式。
