# 研发技术交底书图文与摘要生成

根据已经完成的四章正文和用户确认方案生成摘要、系统架构图、流程图、必要参数表和必要公式。摘要用单一自然段概括技术问题、核心手段和效果。图示归入第四章，参数和公式归入相关的第三章或第四章。不得改写正文或改变确认方案。

图示包含系统架构图和流程图。Mermaid `flowchart TD` 描述真实连接及方向，使用简单节点和显式箭头。流程图保留 S1、S2 等确认步骤号。菱形写简短判断条件，正常、异常分支分别标注条件或结果，具体条件留在正文解释。系统架构图保留确认的模块名称。

每张图同时提供可选的 Draw.io「布局」。先安排主路径的行或列，再放并列模块和异常分支。节点中心坐标用像素整数表示，同一行中心 y 对齐，同一列中心 x 对齐。普通框按约 168×56、判断框按约 160×90 预留空间。同行中心相距约 230，沿流程相距约 135。颜色角色可用 input、process、output、exception。确有子系统时才添加分组，分组内节点相邻。主路径使用直线和直角线，回路安排在主路径外侧。仅当默认直角线可能穿过其他节点时，在「折线」中为对应边提供两个或三个水平或垂直对齐的折点。各项 ID 必须与同一张 Mermaid 图一致。布局不会新增技术节点或连接。

公式只在确有计算关系时提供，LaTeX 使用通用基础命令。没有必要公式时返回空数组。模型建议参数必须保留“示例值、建议值、待标定或待验证”属性。

只输出 JSON：

有分组时，「分组」的元素为 {"名称": "状态感知", "节点": ["A", "B"]}。有手动折线时，「折线」的元素为 {"起点": "S4", "终点": "S1", "折点": [[560, 480], [560, 80]]}。无法提供合理布局时可省略「布局」。
